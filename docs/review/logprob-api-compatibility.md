# Logprob API compatibility boundary

The documented logprob promise is HTTP JSON. That does not make existing Python helper results interchangeable with opaque spans. `LogprobEntries.take`, `spell`, `openai_chunks`, `openai_collect`, `logprob_span`, `_structured_logprobs` and `structured_chunks` construct, slice or retain actual builtin dict/list/string/byte-list values. Nested values may escape independently. Keep their ordinary behavior and direct tests unchanged.

The current production network route runs through `Service`, the private OpenAI handler, generic JSON/SSE writers and monitoring capture/records. MCP model events enter that route too. HTTP client JSON decoding in a different process does not alias the server's result arena. Responses has a separate assembler and currently empty LP arrays. The SYCL server's generic helper monkeypatch is another ordinary route to preserve. Replica/split wrappers forward dynamically: the real captured engine and epoch matter more than the wrapper's class.

A distinct private strict wire path could avoid server-side builtin LP materialization while preserving wire spelling, fields, structured behavior and monitor outputs. It must cover all enumerated production network consumers and must not globally change generic helpers or silently return Unsupported. Monitoring's shallow record copies and retained strings can outlive the turn; they need explicit paid retention if their representation changes.

No standalone strict-owned Python embedding ABI returning LP builtins was located in the bounded source/documentation map. That is not proof arbitrary external callers do not exist. If strict builtin-return behavior is supported, each independently escaping value still needs a genuine payer through final free; an outer wrapper, serializer, cancellation or HTTP-finally is insufficient. Resolve that requirement explicitly before implementing the [proposed strict wire adapters](owned-request-result-proposal.md).
