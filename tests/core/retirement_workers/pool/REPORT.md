# ExpertPool stop-only retirement

Source-only. No compiler, test, container, model or GPU execution. Changes are confined to pool.hpp/pool.cpp; current pins in source-pins.json, prior pins/copies alongside.

`stop_after_dispatch_callers_joined()` returns false on active/failed/sealed state without setting worker stop or joining. Idle transitions atomically to sealed, publishes worker stop, joins each joinable worker, then marks joined. Repeated joined calls succeed. Join/wake exceptions mark failed. Buffers, job/source/format pointers, NUMA planning, and diagnostic publication remain intact until ordinary destruction. No allocation introduced in stop. This method requires the real controller to finish pending windows/doorbells and join all host dispatch callers while source/dispatch owners are still retained. Idle alone is not proof that a future GPU doorbell cannot need a new dispatch. No concurrent destruction, self-delete, or calls on an expired pool are supported.

Each public run variant acquires one idle-to-active gate before even empty work. Private implementations preserve existing arithmetic and internal split fallbacks bypass the outer gate. Concurrent or post-seal run throws logic_error before work; rejected callers do not change active state. Successful outer completion releases idle. Exceptional outer completion marks failed permanently, because unwinding does not prove an already-published batch finished. Destruction refuses an unresolved state via terminate rather than stopping workers underneath a done waiter or freeing their scratch. Caller scope must likewise fail-stop before stack-borrowed dispatch/job buffers disappear after such an exception: a failed pool flag cannot retain arbitrary stack storage. Driver integration is still required.

This changes lifecycle error semantics and adds one atomic compare/exchange and one release store per public dispatch, including legacy paths; performance is UNMEASURED. No existing owned-mode toggle is carried by ExpertPool. Numerical statements remain in the original implementations, but default byte identity/performance and CUDA/HIP/Metal/default/SYCL compatibility are NOT qualified. SYCL has a separate pool implementation and receives no stop API implementation here; its retirement remains an explicit separate gate.

## Prepared fixtures

Prepared checks: active refusal preserves service/active state; concurrent run throws; dispatch completes before retry; all variants enter once including split fallback; successful stop joins and retains a sentinel buffer; repeated stop succeeds; every run variant refuses after seal including zero jobs; exceptional dispatch stays failed and stop refuses; empty pool closes.

Fixture limitation: it does not execute actual kernels, original worker claim/NUMA machinery, real source callbacks or GPU doorbells. Real pool integration, destructor fail-stop subprocess, worker join failure injection, actual controller ordering, and backend compile/link gates remain required. Assertions require a non-NDEBUG fixture build. No claimed red/green or runtime performance result.
