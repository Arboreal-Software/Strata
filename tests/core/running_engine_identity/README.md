# Running executable identity CPU fixtures

`running_engine_identity_test` compiles the actual producer and synthetic test with `STRATA_RUNNING_ENGINE_IDENTITY_TEST` private to that executable. Five separately compiled support units use the actual manifest parser, input bundle, artifact, budget and hash code without that macro. The production collector in `strata_window_state` is untouched and has no syscall seam enabled.

`running_engine_manifest_test` reuses the same five support objects for the strict-manifest regression, with no test syscall macro. It complements the existing engine-linked `verified_input_manifest_test`, which is unchanged. Neither new target links the engine, cudart, HIP or other GPU libraries. The producer test mocks its process syscalls; it never opens the actual `/proc/self/exe`. Filesystem fixtures contain tiny generated bytes, not model payloads.

Registration is inside the existing Linux optional window-state/conversation-test block. Build the two named targets and select the corresponding CTests in an authorized CPU window. Assertions and ASan/UBSan are enabled; each CTest has a45second timeout. Build resource limits remain the invoking environment's responsibility. No source extraction is used, so no extraction freshness checker is necessary. Driver pins are contextual; these tests do not compile or execute the driver integration.

The frozen standalone CPU producer/manifest source closure passed in its separately recorded run. This new public CMake registration is source-only and has not been configured, compiled or run. It supplies no real-process image, DSO/JIT closure, GPU or backend qualification. The frozen candidate remains unchanged.
